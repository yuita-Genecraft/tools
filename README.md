# tools — ブラウザだけで動く道具

AIで開発する人向けの、ページの中だけで動く小さな道具です。外部APIを使わず、あなたのファイルを外に送りません（ページ側の CSP で通信そのものを禁止しています）。

| 道具 | 中身 | ソース |
|---|---|---|
| Claude Code 通知表 | `~/.claude/projects` のログを集計し、推定作業時間・使った日数・よく使ったツール・APIトークン料金の換算を通知表の画像にする（「ありがとう」などの回数と称号はおまけ） | `cc-tsuchihyo/app.html` |
| Firebase 公開前チェック | [fbcheck](https://github.com/yuita-Genecraft/fbcheck)（Node版）と同じ判定をブラウザで。フォルダをドロップするだけ | `fbcheck-web/app.html` |
| Claude Code 生存率 | `~/.claude/projects` のログと、手元のプロジェクトのフォルダを突き合わせて、Claude が書いた行のうち今も残っている割合を「残った・Claude が自分で書き直した・人が消した・ファイルごと消えた」に分けて1枚の画像にする。会話ごとに最初の指示と「残った1行あたりの出力トークン」を並べ、今は無いコードに使った出力トークンの割合を出す（どの頼み方が高くついて消えたか）。人が直した行から直し癖（直しの型）を数え、CLAUDE.md に足す1行の案を出す。結果を JSON で保存して次回と比べられる。期間つきの AI率、人が消した行が多いファイルも | `cc-seizon/app.html` |

## 仕組み

- `*/app.html` は claude.ai の Artifact 用（doctype などの骨格なし）
- `build_standalone.py` で doctype・CSP・OGP を付けた単体の HTML にする
- `build_site.py <公開先URL>` で GitHub Pages 用の `docs/` を作る
- X などのカード画像は `docs/og/*.png`。`og/*.html` を `render_og.py` で撮って作る。通知表のカードは `--card` で渡した画像を使う（公開中の画像は作者の実際の通知表）。渡さない時は、アプリの見本をその場で描いて使う
- CSP は `default-src 'none'; connect-src 'none'` ほか。fetch / XHR / WebSocket はブラウザが止める

  - `test/e2e_fb.py`：テスト用プロジェクト8種（`test/gen_fbproj.py` が作る）。git の外の5種はブラウザ版と CLI の結果が一致するか、本物の git リポジトリの3種は CLI が git の答えどおりに出すか・ブラウザ版が「未確認」で出すか。あわせて言い過ぎ・偽PASSが出ないか
  - `test/unit_engine.mjs`：.gitignore の読み・ルールの読み・文言（言い過ぎ）の単体テスト

### 通知表の自動E2E

`main` 向けのPR（Draftを含む）の作成・更新・再オープン時に、GitHub Actions の `Notification report E2E` が通常の集計比較と重複時間テスト、生存率の突き合わせ（`test/e2e_seizon.py`）を実行します。Python 3.12 / Playwright 1.58.0 / Chromiumを使用し、入力はテストが生成する合成ログだけです。集計の不一致やテスト例外はジョブ失敗になります。通常の比較が失敗しても、ブラウザの準備が完了していれば重複時間テストも実行します。

実行結果はPRのChecksまたはActionsの各ステップのログで確認できます。デスクトップ・モバイルの見本画面の横はみ出し、収集したブラウザエラー・警告、Playwrightのrequestイベントで観測した外部リクエストも失敗判定に含みます。CSP有効の検証では見本画像のPNG読み込み完了を待ち、ブラウザエラーと外部リクエストを判定します（この検証のconsole警告は収集対象外）。`file:`・`data:`・`blob:`はローカル表示用として許可します。全画面状態や全通信経路の保証ではなく、Firebase公開前チェックのテストもこのワークフローの対象外です。

公開リポジトリの標準Ubuntuランナーでのみ実行し、非公開リポジトリではジョブをスキップします。追加の保存容量課金を避けるため、artifactアップロードとActionsキャッシュは使いません。スクリーンショットは実行中に生成されますが、ジョブ終了後には保存されません。ログはGitHubの保持設定に従います。このワークフローはdeploy・`docs/`更新・自動mergeを行いません。

ローカルで同じテストを実行する場合：

```sh
python -m pip install -r test/requirements-e2e.txt
python -m playwright install --with-deps chromium
python -u test/e2e.py
python -u test/test_overlap.py
```

## 集計で気をつけたこと（生存率）

- 「Claude が書いた行」＝Edit の new 側にあって old 側に無い行、Write は Read で見えていた行（と `toolUseResult.originalFile`）を除いた行。行は前後の空白を落として空白をそろえて比べ、4文字未満と記号だけの行は数えない（厳密モードで切り替え）
- 4分類＝今も同じ行で残っている／Claude が後の Edit の old 側か Write の書き換えで自分で消した／今もあるファイルの中で、それ以外に無くなった（人が消した・直した・Bash で消した）／ファイル自体が今のフォルダに無い（ファイルごと消えた＝捨てた試作・名前を変えたファイル）。人が少し直した行は「残った」に入らない＝下限の値
- 「ファイルごと消えた」を分けたのは、本人の実データ（2026-10-20）で、人が消した 2,454 行のうち 2,113 行が捨てた試作フォルダ一式だったから。混ぜると「人が直した」が実態の6倍に見える。判定（赤ペン先生など）はこれを「人が手を入れた」に数えず、カードの所見に「ファイルごと消えた分を除くと NN%」を添える。頭の数字（生存率）は全部の行で出す＝下限のまま
- 直し癖（CLAUDE.md の1行）＝人が直した Claude の行を、今の行と突き合わせて型に分ける。突き合わせは hunk 方式：Claude が書いた並び（同じ Edit／Write の中）で「残っていない行の連なり」を切り、その前後で残った行を今のファイルでの位置の目印にして、その窓の中の Claude の行でない今の行から1対1で探す（語の集合の重みつき Dice＝予約語・短い語・数字は 0.15、それ以外と文字列は 1。窓の中は 0.5 以上か「中身の語を共有して 0.3 以上」、窓が無い＝塊ごと消えた時はファイル全体から 0.6 以上かつ中身の語の共有）。残りはデバッグ出力・コメントなら削除（コメントは前後が残ったコード行の時だけ癖に数える）、コード行が3行までで窓の残りと同数なら順番で組（小さな書き換え）、3行以上まとまって消えた・書き直されたなら「まとまった削除・書き直し」＝癖ではなく作り直し。型＝書き方の癖（デバッグ出力の削除／コメントの削除／引用符／セミコロン／const 化／any の型付け／コメントの言語／import のパス・拡張子＝パスが変わった時だけ。名前の追加・削除は「その他」）と、内容の直し（名前の変更＝同じ名前の組が2回以上出た時だけ候補／文字列／数値＝後で値が変わっただけで癖とは限らないので、案は観察＋提案の文にし、CLAUDE.md の行としてはまとめない）。候補＝3回以上かつ2セッション以上の型だけ、各型に実例2組と1行の案。会話の中身は見ない（claude-doctor は会話の癖から規則を出す＝根拠が違う）
- 本人の実データ（drive-snippets-mcp・人が直した147行）で最初の版（語の集合の Dice だけ・位置を見ない）を試したら、`it("…")`・`export interface X {`・`.max(N)` のような骨組みが同じだけの別の行を組にして、名前の変更10件・文言の変更9件を出し、消えた機能の JSDoc 32行を「コメントの削除」の癖にしていた＝間違った CLAUDE.md の案が出る。hunk 方式に直した後は、97行が「まとまった削除・書き直し」（機能の削除）、残りは小さな削除・書き換えで候補なし＝正直な答え。2つ目の実データ（handoff-mcp・84行）では、文言の変更13回（仕様の変更でテストの説明の番号が 7→8 になった等）が候補になった＝組は正しいが癖ではない → 「内容の直し」として分けた発端。「人が直した」には、ログに無い経路（git pull・別の作業コピーやクラウドのセッション・Bash）で変わった行も入る＝人の直しの上限で、作業コピーを分ける人ほど「人」が過大になる
- 1行は案であって、守られる保証はない＝入れたら「結果を保存」で数を残し、次回「前回と比べる」でその型が減ったかを見る
- 頼み方（残った1行あたりの出力トークン）＝ログの assistant message の usage（output_tokens）を応答ごとに1回数えて会話ごとに足し（1つの応答は content block ごとに別の行に分かれて書かれ、usage は同じ・流れている途中の行は output_tokens が小さい＝同じ message.id の最大を取る。Codex の指摘・PR #17）、その会話で Claude が書いた行のうちこのリポジトリの行の割合で按分する（別のリポジトリにも触った会話の分は、その割合だけ）。「今は無いコードに使った出力トークン」＝按分した出力トークン × 残っていない行の割合。入力トークン（キャッシュ読み）は数えない＝費用ではなく Claude が書いた量の目安。会話の単位＝`--resume` で再開したセッションは前の message を同じ uuid・新しい sessionId で写しているので、uuid が別の sessionId で出た組をつないで1つの会話にし、写った分は1回だけ数える（代表＝いちばん早く始まった方）。最初の指示＝その会話で最も早い user の text（タグ `<pasted_content …>` などは外す・100字まで）。端末の外に出さず、カードと共有文にも載せない（「指示の冒頭を隠す」もある）。一度消えた行をあとで入れ直したら、今ある行は入れ直した会話のもの（Codex の指摘・PR #17）。順位＝20行以上書いた会話だけ。高くて消えた＝7割以上残らなかった会話を、残った行なし → 残った1行あたりの多い順。安くて残った＝7割以上残った会話を、少ない順
- 発端＝本人の実データ：drive-snippets-mcp の出力 111万トークン（按分）のうち 79% が今は無いコードに使われ、その大半は「HTMLサイトで宇宙再現して。3Dでどこでも行けるように」で始めた1会話（75万・2,448行書いて残った行 0）。一方「git checkout -b fix/… 」で始めた会話は 524行書いて 523行残り、残った1行あたり 116 トークン。トークンと「その行が残ったか」を結びつける道具は ccusage・tokenleak・claude-doctor には無い（2026-10-21 に確認）
- 右の枠に `~/.claude/projects` を入れると、Claude のメモ（memory/*.md）を「コード」として数えてしまう（本人が踏んだ）。.jsonl が3割超・「-Users-…」のフォルダが半数超・一番上の名前が `-` で始まる、のどれかで止める
- ログの絶対パスと、落としたフォルダの相対パスを末尾で照合し、いちばん多く一致した場所を root にする。同じ名前のフォルダが別の場所にある時は一致の多い方
- 失敗した Edit（`is_error`）と、結果の記録が無い Edit／Write は適用しない。tool_use の id で重複を除く（再開したセッションは前の行を写す）
- ログは初期設定で30日より古いものが消えるので、AI率は必ず期間つきで出す。頭に置く数字は生存率

## 集計で気をつけたこと（通知表）

- Claude Code のログは、1つの応答をブロックごとに別の行へ書き、同じ `usage` を行ごとに繰り返す。`message.id` + `requestId` で1回に畳まないと、トークン料金の換算が数倍に膨らむ
- 再開したセッションは前の行を同じ `uuid` で写すことがあるので、`uuid` でも重複を除く
- 料金表は 2026-09-29 時点の [公開料金](https://platform.claude.com/docs/en/about-claude/pricing)。料金表に無いモデルは同じ系列の最新単価で計算し「推定」と表示する
