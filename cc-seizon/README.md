# AI 開発ログマップ · Change Lab

会話の区切り方や圧縮設定を変えた前後を、自分のログで確かめるローカル解析ページ。
先頭で選択条件の最終記録から7日間を調べ、文脈40万超の重み付き量が大きい会話を最大3件、数値根拠付きで示す。無駄・異常の判定ではない。候補の割合の分母は期間内の対象全応答。比較へ進むとAI・作業・モデルを絞るが、会話1件だけの比較にはならず変更日時も自動決定しない。
料金・定額利用枠・作業品質の改善を自動で判定する道具ではない。

## 使い方

1. 「自分のログを読み込む」で Claude Code / Codex / Antigravity のログを選ぶ。
2. 変えた内容・実際の変更日時・比較期間を指定する。日時の入力は表示される端末のタイムゾーン。保存値と集計窓は UTC の絶対時刻。
3. AI・モデル・作業フォルダを絞り、前後の構成と確認点も見る。
4. 「条件ごと保存」で、匿名化した数値イベントと条件を一緒に保存する。「保存データを開く」で同じ計算を再現できる。元ログがない保存データでは、従来の使用量・手直しタブは使わない。

ログは送信しない。生成 HTML の CSP は `connect-src 'none'`。フォント・JS・CSS は埋め込み。
保存データには日時、使用量、モデル、匿名の会話・作業番号が含まれる。本文・コード・元のパスは含めないが、活動記録なので共有前に確認する。変更の名前には本人が入力した文字がそのまま保存される。

## 同じ計算を端末から使う

Node.js 22 以降。HTML も作る場合だけ Python 3 が必要。インストールする追加パッケージはない。

```sh
node cc-seizon/collect.mjs \
  --logs "$HOME/.claude/projects" --logs "$HOME/.codex/sessions" \
  --pivot '2026-10-21T07:00:00+09:00' --days 14 \
  --change '圧縮設定を変えた' \
  --out /tmp/logmap-result.json --html /tmp/logmap-result.html
```

変更日時は例。実際に変えた時刻を指定する。HTML は開くだけで集計済みの画面になる。
既存ファイルは上書きせず、生成ファイルは権限 600。収集は指定場所の JSONL だけで、symlink を辿らず、各ファイルを開いた時点のサイズまで読む。全ファイルが同時刻の原子的スナップショットになるわけではない。処理中の追記は次回取得で入る。
`--html` の作成に失敗した場合でも先に作った JSON は残す（再実行は別の出力名を使う）。
常駐・監視・資格情報の取得・AI 呼び出し・外部送信は行わない。

`parser-node.mjs` はページの純粋なパーサー部分を再利用する。CLI は会話・コード本文を落としてから処理し、ブラウザとの数値・会話群・欠落数の一致を試験する。新しいログ形式は自動的に対応済みとは扱わない。

## 測り方と限界

- 前は `[変更日時 − N日, 変更日時)`、後は `[変更日時, 変更日時 + N日)`。N は 7 / 14 / 30。24 時間ごとの帯も同じ開始時刻基準。記録のない日は空欄。収集日時より先まで窓がある場合は未完了の警告を出す。
- 文脈は入力＋キャッシュ読み＋書き込み。40万 **超** の応答の重み / 全応答の重みを比較し、差はパーセントポイントで示す。母数・重みが 0 の場合は「不明」で、0% として差を出さない。
- 重みは入力1・出力5・キャッシュ読み0.1・書き込み5分1.25 / 1時間2の共通比。金額、モデル単価、定額枠消費を表さない。生のトークン総数も保持する。
- 会話群は、全入力ログで最初に観測した時刻で分ける。窓より前の履歴も使う。再開による写しは既存のID照合でまとめる。実際の会話作成時刻・設定読込の証拠ではない。
- モデルは明示記録だけ。欠落は不明。作業フォルダは最初の cwd で、複数 repo にまたがる会話の厳密な分割ではない。前後の AI / 作業 / モデル構成比が10ポイント超変わると警告する。タスクの難易度を揃えた因果比較ではない。
- サブエージェントの明示フラグは既定で除外。フラグを持たない形式では識別できない。圧縮境界は Claude の明示的な `compact_boundary` のみを数える。
- SHA-256 は数値・条件・解析版の内容照合用。原ログの真正性や完全性の署名ではない。対応外の版、壊れた数値、欠けた会話対応、ハッシュ不一致は読み込まない。
- 従来の手直し分析は、repo の対応候補が曖昧、または選択フォルダ名と候補の末尾が異なる時に数値・提案・共有を止める。同名フォルダだけで同一 repo と保証するものでもない。改名したコピーは元と同名のフォルダか対象ログだけで確認する必要がある。
- 完了時間、受入件数、本人の手間、コードの正しさは未測定。手直しの再発率の独立評価も今後の工程。数値が小さくなるだけでは採用判断にしない。

## 開発と検証

```sh
python3 build_standalone.py cc-seizon/app.html cc-seizon/dist/index.html
node --test test/unit_lab.mjs
python3 test/e2e_lab.py
python3 test/e2e_seizon.py
```

ブラウザ試験は `test/requirements-e2e.txt` の Playwright と Chromium を使う。ローカルの既存ブラウザを選ぶ場合は `PLAYWRIGHT_EXECUTABLE_PATH`。CSP を有効にした新機能 E2E で保存往復・入力拒否・CLI一致・外部通信0・320/390/768pxを確認する。既存の Python 別実装と手計算 fixture による集計回帰も維持。

公開用 `docs/` は `build_site.py` で別途生成する。ソース PR の完了を公開ページの更新とは扱わない。

解析版2では明示的な圧縮境界も会話の最初の観測に含める。版1の保存JSONは元のハッシュを確認してから新版で再計算し、その旨を表示する。再保存は版2。過去の分類結果と同一とは主張しない。

### 実測を受けた入口の見直し
候補ランキングより先に、同じ7日間・条件の全体割合とAI別の割合を表示します。AI別の分母は各AIの全応答です。候補は初期状態で折りたたみ、寄与が小さい候補を異常と受け取らせない構成です。AI切替は作業・モデルを解除し、変更日時を保持。期間は選択AIの最終記録に追従します。比較結果の全AI注意はコピーにも含みます。
会話内の圧縮境界を対象期間内で表示します。同時刻のコピーは重複排除。圧縮境界、応答間隔、別ファイル、cost-state.startTimeは再起動/設定読込の証拠とは扱いません。実ログの再開4ファイルではstartTimeまで同値が引き継がれていたため、再起動時刻の推測表示は実装していません。旧snapshotでも既存compactionsから同じ表示ができます。
